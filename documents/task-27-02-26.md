# Task Tracking - 27/02/2026

## Requirement Changes Summary

### 1. Auth Module Refactoring
- **Multi-role login**: One account can have multiple roles (e.g., user + operator). Login accepts optional `actorType` (default: user). Response includes `availableRoles` list.
- **Role-specific access token**: User token cannot access operator resources.
- **Web registration**: Guest can register on web with email + phone + password. Default role = user.
- **Google OAuth**: Login/register via Google OAuth through Supabase.
- **Remove SMS OTP**: Completely remove SMS OTP flow (no longer used).
- **Shared auth**: Mobile and web share the same registration/login endpoints.
- **No mobile verification gate**: Users with accounts can login on mobile without extra verification.

### 2. New Auth Endpoints
- `POST /auth/register` — Self-service registration (email, phone, fullName, password)
- `POST /auth/google` — Google OAuth via Supabase
- `POST /auth/forgot-password` — Request password reset email
- `POST /auth/reset-password` — Reset password with token
- `POST /auth/change-password` — Change password (authenticated)

### 3. Staff Chat Notes API
- Staff notes about customer interactions, visible to other staff
- New `StaffNote` Prisma model
- CRUD endpoints: create note, list notes by user, get note details

### 4. Removed
- SMS OTP module dependency from Auth
- Guest registration OTP flow endpoints (5 endpoints removed)
- OTP-related DTOs
